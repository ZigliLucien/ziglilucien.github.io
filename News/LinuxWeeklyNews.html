NGINX2Root: Remote Code Execution vulnerabilities in nginx
back

Xint is reporting that it has discovered a collection of five critical vulnerabilities in the NGINX web server. The worst flaw, it says, would allow an unauthenticated attacker to execute commands on an affected nginx server with HTTP/2 enabled. The company also reports a local-privilege escalation (LPE) kernel vulnerability, which was introduced in the 4.15 kernel, in the Stream Control Transmission Protocol (SCTP) subsystem. If chained with the NGINX vulnerability, it would allow an attacker to gain root privileges on the host. A kernel patch for this is not yet available.

We also obtained a root shell on the host in a setup where nginx was running in a Docker container. On many Linux distributions, the SCTP module is installed by default and the kernel loads it automatically the first time a program opens an SCTP socket. Whether SCTP is reachable on a given host still depends on the kernel, the available modules, and the container's restrictions. Where it is reachable, the attacker can take over the host kernel. Since all containers on the host share that kernel, this gives the attacker control of the host and every container on it.

Xint recommends updating to NGINX 1.31.9, which was just released, and to block the SCTP module on hosts that do not need it until a kernel fix is available. See the mitigations section of their report for more information.

Redict deprecated in favor of Valkey
back

Drew DeVault has announced that Redict, a fork of Redis that was created in response to Redis's 2024 license change, has been deprecated. He recommends switching to Valkey, the permissively licensed Redis fork supported by the Linux Foundation. The two projects are mutually compatible, so switching should be as simple as changing which package is installed and renaming the configuration file.

I had hoped to rally the Redis diaspora around a copyleft initiative, to protect ourselves from future rug-pulls, and made Redict to serve this purpose. However, with the valkey project's success, and Redis's return to a copyleft license, Redict was not able to build a sustainable community.

We recommend that Redict users switch to valkey, which uses a permissive license but has better long-term prospects. We advise against switching back to Redis; though it is once again open source, and copyleft, it uses a contributor license agreement which will facilitate another rug-pull when Redis has a bad financial quarter.

[$] Zellij manages terminal workspaces with style
back

Zellij is a relatively new entrant in the terminal-multiplexer category. Like GNU Screen and tmux it gives users the ability to manage a workspace inside a terminal with split panes, provides session management, and so forth; but Zellij also includes a web server for browser access to a terminal session, is extensible via a plugin API, and is likely more beginner-friendly than its predecessors. Its most recent release, version 0.46, adds a standalone terminal emulator, a built-in inbox for notifications, and a settings screen so users can configure the application without fussing with configuration files. While the low version number might suggest that it is not yet ready for serious use, it seems stable and full-featured enough to meet the needs of many users.

[$] A new generation of futexes
back
Futexes are a kernel subsystem that provides support for fast mutexes in user space. While futexes can indeed be fast, they are not fast enough for a number of users. Partly as a result of that, the implementation of futexes has grown in complexity over the years, with two basic variants on offer. The desire for faster futexes remains, though, and that inspires new patches, including this series from Suleiman Souhlal adding a third futex class called "futex PING" for "priority inheritance next generation".

Manjaro Project e.V. non-profit organization created
back

Frank Vandermeiren has announced the creation of the Manjaro Project e.V., a nonprofit organization in Germany that is independent of the Manjaro GmbH & Co KG company. This is following a governance struggle that took place earlier this year between a number of Manjaro Linux contributors and Philip Müller, project lead and CEO of the Manjaro company.

At the moment, we are still working on optimizing the new development infrastructure, which was partly necessitated by the ongoing (A.I.) bot attacks against our old infrastructure.

However, as you may have noticed, the last Testing Updates and Stable Updates were initiated by the Manjaro Team without supervision from Philip Müller — with special thanks to @Yochanan for his hard work!

Dennis ten Hoove has indicated that "a transfer of company assets to the e.V. has not yet taken place", and the group's next step is to ready the nonprofit for the transition and "reach out and engage in dialogue with the company".

Announcing XRAID: declustered parity RAID for zoned XFS
back

Christoph Hellwig has announced the initial public release of XRAID—declustered parity RAID that is integrated into XFS.

The two primary aims of XRAID are to support parity RAID on zoned devices like SMR hard drives, and to provide a fast RAID implementation without inherent data integrity problems. XRAID, just like zoned XFS also works on conventional hard drives and SSDs. Optimizing for SSD performance has not been a focus, but even without that, writes are up to 20 times faster than mdraid. [...]

Work on XRAID has been ongoing for a year and a half, and while we aren't anywhere near ready for an upstream submission, we are interested in feedback and testing from a wider audience now. The current implementation supports zero to 2 parities. We did experiments with the SnapRAID parity library to support 3 and more parities, and while that is not included in the current version, support for more parities is planned and the code is prepared for it.

The xfsprogs branch includes mkfs support and a new "xraid" utility for managing devices and inspecting an XRAID file-systems. We have also extended Zonar (The zoned file-system visualisation tool) to show how each logical zone maps onto physical zones on devices.

Hellwig gave a presentation at FOSSY in August on this topic; video of the talk does not seem to be available yet, but his slides are available.
